    From keystrokes to a running process

    Almost every "weird" shell behaviour stops being weird once you know the exact sequence the shell follows between Enter and the program starting.

    You will be able to

    • List the stages a line goes through, in order, and predict what a program receives
    • Tell builtins, functions, aliases and external programs apart, and say why it matters
    • Explain PATH lookup, fork/exec, the environment and exit status

    The pipeline inside the shell

    1. Read and tokenize. The line is split into words and operators (| && ; >). Quotes and backslashes decide what counts as one word. Aliases are substituted here, on the first word only.
    2. Parse. Tokens become a tree: lists of pipelines of commands, plus compound commands (if, for, { }, ( )).
    3. Expand each word, in this fixed order: brace expansion, tilde, then parameter / command / arithmetic substitution (left to right), then word splitting, then pathname expansion (globbing), and finally quote removal.
    4. Redirect. Files are opened and file descriptors rearranged, left to right.
    5. Execute. The first word names a function, builtin or program. For a program the shell forks a copy of itself and the child calls execve with an argument array and an environment.
    6. Wait. The shell collects the child's exit status into $?.

    The program never sees your quotes, your *, or your $HOME. It gets a finished array of strings. The sandbox has a helper, argv, that prints that array so you can stop guessing:

    $ argv *.md "$HOME" '$HOME' ~ notes/*
$ argv a   b    "c   d"
$ x="one two"; argv $x "$x"
$ argv {1..3}{a,b}
$ argv "" $nothing ''

    Study the third and fifth lines. An unquoted variable is split into words and each word is glob-expanded; an unquoted empty variable vanishes entirely, while "" is a real, empty argument. That one rule causes more script bugs than everything else combined, and Module 02 is about it.

    PATH, fork and exec

    PATH is a colon-separated list of directories searched left to right for a file with the execute bit. Names containing a slash skip the search, which is why you run local programs as ./prog: the current directory is deliberately not in PATH, so a file named ls in a downloaded archive cannot hijack your commands.

    $ echo $PATH
$ PATH= ls  # an empty PATH for one command
$ env | head -5
$ FOO=bar env | grep FOO  # one-shot environment for a single command
$ FOO=bar; bash -c 'echo "child sees: [$FOO]"'
$ export FOO; bash -c 'echo "child sees: [$FOO]"'

    A variable is private to the shell until you export it; exported variables are copied into each child's environment at exec time. Copied, not shared: a child can never change its parent's variables.

    Exit status is the shell's boolean

    Every command returns 0 to 255. Zero means success; anything else is failure, and the specific value belongs to the program (grep: 1 = no match, 2 = error). The shell reserves 126 (found but not executable), 127 (not found) and 128+N (killed by signal N, so 130 is Ctrl-C). if, while, && and || all test exit status, never output.

    $ grep -q op /etc/passwd; echo $?
$ grep -q nosuchuser /etc/passwd; echo $?
$ grep -q x /no/such/file; echo $?
$ nosuchcommand; echo $?
$ mkdir /tmp/demo && cd /tmp/demo && pwd
$ cd /nonexistent || echo "could not cd, staying in $PWD"
$ if grep -q wheel /etc/group; then echo "wheel exists"; fi
    fish: the stages are the same, with two friendlier rules. Variables are lists and are never word-split, so $x behaves like bash's "$x". And $status replaces $?.

    You run rm $file where file="my report.txt". What does rm receive?

    Parameter expansion happens first, then word splitting on the unquoted result. "$file" suppresses the split.

    Which happens first?

    Braces expand before anything else, which is why {1..$n} does not work in bash: the variable has not been expanded yet when the braces are examined.

    The script ran in a child process. Its working directory died with it. source script.sh would run it in your shell.

    A command exits with status 137. What most likely happened?

    128 + 9. Typical causes: someone ran kill -9, or the kernel's out-of-memory killer chose it.

    Quoting and the seven expansions

    Expansions are the shell's standard library. Knowing them well removes most calls to sed, basename and expr, and knowing the quoting rules removes most bugs.

    You will be able to

    • Choose between no quotes, double quotes, single quotes and $'...' on purpose
    • Use parameter expansion for defaults, trimming, replacement, substrings and case
    • Work with arrays, arithmetic, brace expansion and globs without surprises

    Four ways to quote

    FormExpandsUse for

    You cannot put a single quote inside single quotes. The idiom 'it'\''s' closes the quote, adds an escaped quote, and reopens. Adjacent quoted pieces join into one word.

    Rule: double-quote every expansion unless you can say why not. "$var", "$(cmd)", "$@", "${arr[@]}". Unquoted is the special case.

    Command and arithmetic substitution

    $(command) runs the command in a subshell and substitutes its stdout with trailing newlines removed. It nests cleanly; the old backtick form does not, so avoid it. $((expr)) evaluates integer arithmetic with C operators, and variables inside need no $.

    $ echo "kernel $(uname -r) on $(hostname)"
$ lines=$(wc -l < logs/access.log); echo "$lines requests"
$ echo $(( (lines + 9) / 10 ))  # integer division, rounded up
$ echo $(( 0x1000 + 0x20 ))  $(( 1 << 12 ))  $(( 0xFF & ~0x0F ))
$ printf '0x%08x\n' $(( 0x10000 + 4 * 4096 ))
$ n=5; (( n++ )); (( n > 5 )) && echo "n is now $n"
    On the bench: shell arithmetic understands hex and bit operators, which makes it a handy calculator for flash offsets and register masks. It is integer only: for floating point use awk 'BEGIN{print 3.3*4095/4096}' or bc -l.

    Brace expansion and globs

    Braces generate words whether or not files exist; globs match existing names. Braces run first, so they can produce globs.

    $ echo {a,b,c}.txt img{01..04}.png {x..z}
$ cp conf/serial.conf{,.bak}; ls conf  # the classic backup idiom
$ ls src/*.c
$ ls src/[mu]*.[ch]
$ ls src/*.{c,h}  # braces first, then two globs
$ echo src/*.xyz  # no match: the pattern is passed through unchanged

    That last line is a trap: when nothing matches, bash leaves the pattern as a literal string, so for f in *.log runs once with f='*.log' in an empty directory. Guard with [[ -e $f ]] || continue, or enable shopt -s nullglob in scripts. Globs skip dotfiles unless the pattern starts with a dot, and ** recursion needs shopt -s globstar.

    Arrays

    Whenever you hold a list of things (files, arguments), use an array. A string with spaces in it cannot represent file names that contain spaces.

    $ files=(src/*.c "notes/my notes.txt")
$ echo "${#files[@]} items, first: ${files[0]}"
$ for f in "${files[@]}"; do echo "- $f"; done
$ files+=(Makefile); echo "${files[@]: -2}"
$ args=(-l -h --); ls "${args[@]}" src | head -3  # build a command safely
$ declare -A baud=([esp32]=115200 [atmega]=57600); echo "${baud[esp32]} ${!baud[@]}"

    "${arr[@]}" expands to one word per element. Without the quotes, or with *, elements get re-split. The same holds for "$@", the array of a script's arguments.

    fish: no word splitting, so most of this pain is absent. Lists are native (set files src/*.c, $files[1], 1-indexed), command substitution is (cmd), arithmetic is math, and string surgery is string replace, string split, path basename.

    A glob expands directly to one word per file, with no splitting. Command substitution output is split on whitespace, breaking such names.

    File descriptors, pipes and redirection

    A process does not know about your terminal. It knows three numbered slots, and the shell decides what each one is connected to before the program starts.

    You will be able to

    • Reason about any redirection as edits to a file-descriptor table, in order
    • Route stdout and stderr independently, including through pipes
    • Use here-documents, process substitution, tee, PIPESTATUS and pipefail

    The descriptor table

    Each process has a table of open files indexed by small integers. By convention 0 is stdin, 1 is stdout, 2 is stderr. A redirection is an instruction to the shell: "before exec, make slot N point here". They are applied left to right, and N>&M means "make N a copy of whatever M points to right now".

    SyntaxEffect on the table
    > f / >> f1 → f, truncating / appending
    2> f2 → f
    < f0 ← f
    > f 2>&11 → f, then 2 → (where 1 points) = f. Both in f
    2>&1 > f2 → (where 1 points) = terminal, then 1 → f. Errors still on screen
    &> fbash shorthand for > f 2>&1
    >&21 → where 2 points: how scripts print error messages
    2>/dev/nullDiscard errors
    a | ba's 1 → pipe → b's 0, set up before a's own redirections

    The sandbox has a command built for practising this. sensor-scan writes three lines to stdout and two to stderr and exits with status 3:

    $ sensor-scan
$ sensor-scan > /dev/null  # only the stderr lines remain
$ sensor-scan 2> /dev/null
$ sensor-scan > /tmp/both 2>&1; cat /tmp/both
$ sensor-scan 2>&1 > /tmp/out  # order matters: errors still reach the screen
$ sensor-scan 2>&1 | grep -c node  # both streams through the pipe
$ sensor-scan 2>&1 >/dev/null | tr a-z A-Z  # only stderr through the pipe
    Truncation happens first. In sort f > f the shell empties f before sort reads it. Use sort -o f f, sed -i, or write to a temp file and mv. And sudo echo x > /etc/file fails because your unprivileged shell opens the file, not sudo: use echo x | sudo tee /etc/file.

    Pipes

    A pipe is a kernel buffer (64 KiB by default) with a write end and a read end. Every stage of a pipeline starts at the same time; they are not run one after another. A writer blocks when the buffer is full, a reader blocks when it is empty, and when the reader exits the writer receives SIGPIPE, which is why yes | head -1 terminates.

    Each stage runs in its own subshell, which has a famous consequence:

    $ count=0; cat logs/app.log | while read -r line; do count=$((count+1)); done; echo "count=$count"
$ count=0; while read -r line; do count=$((count+1)); done < logs/app.log; echo "count=$count"
$ sensor-scan | grep ok; echo "status: $?  all: ${PIPESTATUS[@]}"
$ set -o pipefail; sensor-scan | grep -q ok; echo "with pipefail: $?"; set +o pipefail

    The first loop counted inside a subshell and the result was thrown away. Redirecting into the loop keeps it in your shell. The exit status of a pipeline is the status of its last command unless pipefail is on, so a failing producer goes unnoticed by default.

    Process substitution

    <(cmd) runs cmd and gives you a file name (like /dev/fd/63) whose contents are its output. It lets commands that insist on file arguments read from pipelines, and it avoids temp files.

    $ echo <(true)  # it really is just a path
$ diff <(sort data/calibrated.txt) <(cut -d, -f2 data/sensors.csv | sed 1d | sort -u)
$ comm -12 <(grep -oE '[0-9.]{7,}' logs/access.log | sort -u) <(grep -oE '[0-9.]{7,}' logs/auth.log | sort -u)

    That last command answers "which addresses appear in both the web log and the SSH log?" in one line.

    Check yourself

    Where do error messages go in make 2>&1 > build.log?

    When 2>&1 is processed, fd 1 still points at the terminal, so 2 becomes a copy of that. Only afterwards is 1 moved to the file.

    false | true; echo $? prints…

    Without pipefail only the last stage counts. ${PIPESTATUS[@]} would show 1 0.

    Why does sudo echo 1 > /proc/sys/net/ipv4/ip_forward fail?

    Redirections are performed by the invoking shell. echo 1 | sudo tee /proc/sys/net/ipv4/ip_forward opens the file inside the privileged process.

    In cat big.log | grep ERROR | head -1, what stops cat once head has its line?

    head exits, grep gets SIGPIPE on its next write and exits, then cat gets SIGPIPE in turn. The pipeline unwinds from the right.

    Aliases versus functions

    An alias is a text replacement for the first word; it cannot take arguments in the middle. As soon as you need $1, write a function. Functions are also what you use to wrap a command with safer defaults.

    $ alias gl='grep -rn --include=*.c'
$ gl TODO src
$ mkcd() { mkdir -p "$1" && cd "$1"; }
$ mkcd /tmp/proj/build; pwd
$ hd() { hexdump -C "$@" | head -20; }
$ hd fw/firmware.bin
$ type mkcd
$ unalias gl; unset -f hd

    grep and regular expressions

    Logs, configs, source code, serial captures: it is all text, and a regular expression is how you describe the lines you care about. Learn one dialect properly and the rest are footnotes.

    You will be able to

    Check yourself

    Which pattern matches a line that consists only of digits?

    Without anchors a pattern matches anywhere in the line, and [0-9]* even matches the empty string, so it matches every line.

    sed: edit text without opening it

    sed applies a small program to each line of its input. Ninety percent of real use is substitution and line selection, and those two cover config edits, log slicing and bulk refactors.

    • Substitute with capture groups, alternative delimiters and flags
    • Select lines by number, pattern and range, and print, delete or change them
    • Edit files in place safely

    Substitution

    $ echo 'baud=9600 baud=9600' | sed 's/9600/115200/'  # first match per line
$ echo 'baud=9600 baud=9600' | sed 's/9600/115200/g'  # every match
$ echo 'baud=9600 baud=9600' | sed 's/9600/115200/2'  # only the second
$ echo '/usr/local/bin' | sed 's|/usr/local|/opt|'  # any delimiter: no leaning toothpicks
$ echo 'Error error ERROR' | sed 's/error/E/gI'  # case-insensitive
$ echo 'port 8080' | sed -E 's/[0-9]+/[&]/'  # & is the whole match
$ echo '2026-11-10' | sed -E 's/([0-9]+)-([0-9]+)-([0-9]+)/\3.\2.\1/'  # reorder with groups
$ sed -E 's/^([^,]*),([^,]*),.*/\2 -> \1/' data/parts.csv | head -4

    Use -E so groups are plain ( ). In the replacement, & is the entire match and \1…\9 are the groups. The p flag prints lines where a substitution happened, which with -n gives you "grep and transform" in one step:

$ sed -nE 's/^interval=(.*)/\1/p' /etc/sensor-logger.conf  # read one config value

$ sed '1d' data/parts.csv | head -3  # drop the header

$ sed '/^#/d; /^$/d' conf/serial.conf  # two commands, separated by ;
$ sed -n '/ERROR/{s/^[^ ]* //;p}' logs/app.log | head -3  # a block on matching lines
$ sed '3q' logs/access.log | cut -c1-50  # like head -3, and stops reading
$ sed -n '/node-d/=' data/sensors.csv | head -3  # print line numbers of matches

    Editing files in place

    -i rewrites the file. Always look at the result without -i first, and keep a backup with a suffix until you trust the expression: sed -i.bak '...' file.

    $ cat conf/serial.conf
$ sed 's/^parity=none/parity=even/' conf/serial.conf  # preview on stdout
$ sed -i.bak 's/^parity=none/parity=even/' conf/serial.conf
$ diff conf/serial.conf.bak conf/serial.conf
$ sed -i '/^stopbits/a flow=none' conf/serial.conf; tail -3 conf/serial.conf  # append after a match
$ sed -i -E 's/^#?(PermitRootLogin).*/\1 no/' conf/sshd_config; grep PermitRoot conf/sshd_config

    That last form is the standard way to set a config key whether or not it is currently commented out: optional #, capture the key, replace the whole line.

    Anchor your patterns. s/9600/115200/ will also rewrite a comment, a port number or a timestamp that happens to contain 9600. s/^baud=9600$/baud=115200/ changes exactly one thing. macOS/BSD sed differs: -i '' needs an explicit empty suffix and several GNU extensions are missing.

    When to stop using sed

    sed works line by line and has no notion of fields or numbers. If you find yourself reaching for the hold space (h, G, x) or counting columns, switch to awk. If the data is JSON or YAML, use jq or yq: regexes cannot parse nested structures.

    awk: a programming language for columns

    awk reads records, splits them into fields, and runs your pattern-action rules. It has variables, arithmetic, associative arrays and printf. For tabular text it replaces most small Python scripts.

    You will be able to

    • Select and reformat fields with any separator
    • Filter rows with numeric and regex conditions
    • Aggregate with associative arrays: counts, sums, averages, min and max per key

    The program shape

    awk 'BEGIN { setup }  pattern { action }  pattern { action }  END { summary }' file

    For every input line awk sets $0 (the line), $1…$NF (the fields), NF (field count) and NR (line number), then runs each rule whose pattern is true. A rule with no action prints the line; a rule with no pattern runs on every line.

    $ awk '{print $1}' logs/access.log | head -3  # first whitespace-separated field
$ awk '{print $1, $9, $NF}' logs/access.log | head -3  # comma = output separator (space)
$ awk -F, '{print $2}' data/parts.csv | head -4  # -F sets the input separator
$ awk -F: '$3 >= 1000 {print $1, $7}' /etc/passwd  # numeric condition
$ awk -F, 'NR > 1 && $4 >= 4' data/parts.csv  # pattern only: print the line
$ awk '/ERROR/ {n++} END {print n, "errors"}' logs/app.log
$ awk 'NR == 5, NR == 7' logs/app.log  # a range of records
$ awk 'END {print NR}' logs/access.log  # wc -l
$ awk '{print NF}' logs/app.log | sort -n | uniq -c  # how many fields per line?

    Always wrap the program in single quotes: awk's $1 must reach awk, not be expanded by the shell. To pass a shell value in, use -v name="$value".

    Conditions and regexes

    $ awk '$9 == 404' logs/access.log | wc -l
$ awk '$9 >= 400 {print $9, $7}' logs/access.log | sort | uniq -c | sort -rn | head -4
$ awk '$7 ~ /^\/api\//' logs/access.log | wc -l  # field matches regex
$ awk '$1 !~ /^192\.168\./ {print $1}' logs/access.log | sort -u  # does not match
$ awk -F, -v limit=3.3 'NR > 1 && $5 < limit {print $2, $5}' data/sensors.csv | head -4
$ awk -F'[][]' '{print $2}' logs/access.log | head -2  # a regex as separator: text inside [ ]

    printf and built-in functions

    $ awk -F, 'NR > 1 {printf "%-4s %-18s %3d x %6.3f = %7.2f\n", $1, $2, $4, $5, $4*$5}' data/parts.csv
$ awk -F, 'NR > 1 {print toupper($2), length($2)}' data/parts.csv | head -3
$ awk '{print substr($4, 2, 11), substr($4, 14, 5)}' logs/access.log | head -2  # date and time
$ awk '{split($4, t, ":"); print t[2]}' logs/access.log | sort | uniq -c  # requests per hour
$ awk '{gsub(/[0-9]+/, "N"); print}' logs/app.log | cut -c1-60 | head -3
$ awk 'BEGIN {printf "%.4f V per LSB\n", 3.3 / 4096; print 2^10, 17 % 5, int(7/2)}'
    On the bench: a BEGIN-only program is a floating-point calculator that reads no input: ADC scaling, RC time constants (awk 'BEGIN{print 10e3*100e-9}'), baud-rate divisor error. printf "%x" and strtonum("0x1F") (gawk) cover hex.

    Associative arrays: the reason to learn awk

    An array indexed by strings turns "group by" into one line. Accumulate while reading, report in END.

    $ awk '{c[$1]++} END {for (ip in c) print c[ip], ip}' logs/access.log | sort -rn | head -4
$ awk '{b[$9] += $10} END {for (s in b) print s, b[s]}' logs/access.log | sort
$ awk -F, 'NR > 1 {s[$2] += $3; n[$2]++} END {for (k in s) printf "%s %.2f\n", k, s[k]/n[k]}' data/sensors.csv | sort
$ awk -F, 'NR > 1 && (!($2 in lo) || $5 < lo[$2]) {lo[$2] = $5} END {for (k in lo) print k, lo[k]}' data/sensors.csv | sort
$ awk '!seen[$1]++ {print $1}' logs/access.log | head -5  # unique, keeping first-seen order
$ awk -F'[][ ]+' '{c[$3]++} END {for (l in c) print l, c[l]}' logs/app.log | sort  # lines per log level

    !seen[$1]++ deserves a second look: the first time a key appears its count is 0 (false), ! makes it true so the line prints, and ++ ensures every later occurrence is false. It is sort -u without sorting. The iteration order of for (k in arr) is unspecified, so pipe to sort when order matters.

    Files, inodes and permissions

    "Permission denied" is never random. Every access is a lookup of three numbers against nine bits, and once you can do that lookup in your head you can fix it without chmod 777.

    You will be able to

    • Read and set modes in both octal and symbolic form, including setuid, setgid and sticky
    • Explain what read, write and execute mean on a directory
    • Reason about inodes, hard links, symlinks, umask and ownership

    The inode

    A directory is a table of name → inode number. The inode holds everything else: type, mode bits, owner, group, size, timestamps, link count and the location of the data. The name is not in the inode, so one file can have several names (hard links), and renaming never touches the data.

    $ ls -li data/parts.csv
$ stat data/parts.csv
$ stat -c '%i %h %a %U:%G %s %n' data/parts.csv /dev/null /dev/ttyUSB0 ~
$ ln data/parts.csv /tmp/hard; ln -s ~/work/data/parts.csv /tmp/soft
$ ls -li data/parts.csv /tmp/hard /tmp/soft  # same inode twice, link count 2
$ readlink /tmp/soft; readlink -f /bin/sh
$ rm /tmp/hard /tmp/soft

    The nine bits

    -rwxr-x---  1 op  wheel  4096 Nov 10 09:12 deploy.sh
│└┬┘└┬┘└┬┘     │   │
│ │  │  │      │   group
│ │  │  other  owner
│ │  group bits
│ user (owner) bits
type: - file  d directory  l symlink  c char device  b block device  s socket  p pipe

    The kernel checks in this order and uses the first class that applies: are you the owner? then the user bits decide, and only those. Otherwise, are you in the file's group? then the group bits. Otherwise the other bits. Root bypasses the check (except that executing still needs at least one x bit).

    BitOn a fileOn a directory
    r (4)Read the contentsList the names in it
    w (2)Modify the contentsCreate, rename and delete entries in it
    x (1)Execute itTraverse it: reach anything inside by name

    Two consequences surprise people. Deleting a file needs write permission on the directory, not on the file: deletion edits the directory. And a directory with x but no r lets you open files whose names you already know while hiding the listing.

    $ ls -l perm
$ cat perm/locked.txt  # mode 000, even though you own it
$ chmod u+r perm/locked.txt; cat perm/locked.txt
$ mkdir /tmp/box; echo secret > /tmp/box/file; chmod 311 /tmp/box  # wx only
$ ls /tmp/box  # cannot list
$ cat /tmp/box/file  # but can reach a known name
$ chmod 755 /tmp/box; rm -r /tmp/box

    chmod, both dialects

    $ chmod 640 perm/secret.key; ls -l perm/secret.key  # octal: set all bits at once
$ chmod u+x,go-rwx perm/run.sh; ls -l perm/run.sh  # symbolic: change some bits
$ chmod a=r perm/run.sh; ls -l perm/run.sh
$ chmod -R u=rwX,go=rX perm; ls -l perm  # capital X: execute only where it makes sense
$ chmod -v 600 perm/secret.key

    Octal replaces everything; symbolic edits. The capital X sets execute on directories (and files that are already executable) but not on plain files, which makes chmod -R safe. Common modes: 644 files, 755 directories and programs, 600 private keys, 700 ~/.ssh.

    Ownership and umask

    New files start from mode 666 and directories from 777, minus the bits in your umask. With the usual 022 you get 644 and 755. Only root can chown a file to another user; an owner may chgrp a file to any group they belong to.

    $ umask; umask -S
$ touch /tmp/a; mkdir /tmp/d; stat -c '%a %n' /tmp/a /tmp/d
$ umask 077; touch /tmp/b; stat -c '%a %n' /tmp/b; umask 022
$ id
$ chown root perm/run.sh  # not permitted
$ sudo chown root:wheel perm/run.sh; ls -l perm/run.sh; sudo chown op:op perm/run.sh

    When nine bits are not enough there are ACLs (getfacl, setfacl -m u:alice:rw file; a + after the mode in ls -l signals one), file attributes (chattr +i makes a file immutable even for root) and capabilities (getcap; e.g. cap_net_bind_service lets a non-root service bind port 80 without setuid).

    Check yourself

    A file is -rw-r--r-- root root inside a directory drwxrwxrwx. Can a normal user delete it?

    Unlinking edits the directory. This is exactly what the sticky bit on /tmp prevents.

    You own a file with mode ----rw-rw- and you are in its group. Can you read it?

    The first matching class decides. Owners can always chmod it back, though.

    Which mode makes a shared project directory where new files inherit the group?

    2000 is setgid; 775 gives the group write access. 1777 is /tmp, 4755 is a setuid program.

    With umask 027, a new directory gets mode…

    777 with the 027 bits cleared: rwx r-x ---.

    SSH, tmux, rsync and tar

    Most serious terminal work happens on a machine that is not in front of you: a server, a Raspberry Pi on the bench, a build box. These four tools make a remote machine feel local and keep your session alive when the link drops.

    Keys

    You hold a private key; the server lists your public key in ~/.ssh/authorized_keys. Login proves you have the private half without sending it. Generate one Ed25519 key per machine you type on, protect it with a passphrase, and let ssh-agent remember the passphrase for the session.

    $ ssh-keygen -t ed25519 -C "op@bench"
$ ls -l ~/.ssh
$ cat ~/.ssh/id_ed25519.pub
$ ssh-copy-id lab  # appends the .pub to authorized_keys on lab
$ ssh-add -l

    SSH refuses keys and directories that are too open: ~/.ssh must be 700, private keys 600, authorized_keys 600, and your home directory not group-writable. When key login silently falls back to a password, permissions on the server side are the usual cause; ssh -v host shows each key being offered and rejected.

    • ExecStart needs an absolute path and is not run by a shell: no pipes, ~ or && unless you write ExecStart=/bin/bash -c '...'. A wrong path fails with status 203/EXEC.
    • The service gets a minimal environment, not your .bashrc. Set what it needs with Environment= or EnvironmentFile=.
    • Do not daemonise or write your own log files: stay in the foreground and print to stdout/stderr, and the journal captures it.
    • Hardening is one line each: ProtectSystem=strict, PrivateTmp=yes, NoNewPrivileges=yes, DeviceAllow=/dev/ttyUSB0 rw. systemd-analyze security UNIT scores a unit.

    User units and timers

    You have your own systemd instance. Units in ~/.config/systemd/user/ are managed with systemctl --user, need no root, and hook into default.target. They stop at logout unless you run loginctl enable-linger $USER once.

    # ~/.config/systemd/user/backup.service        # ~/.config/systemd/user/backup.timer
[Unit]                                          [Unit]
Description=Back up ~/work                      Description=Nightly backup

[Service]                                       [Timer]
Type=oneshot                                    OnCalendar=*-*-* 02:30:00
ExecStart=%h/work/scripts/backup.sh %h/work /mnt/nas     Persistent=true        # catch up after downtime

                                                [Install]
                                                WantedBy=timers.target

    $ systemctl --user daemon-reload
$ systemctl --user enable --now backup.timer
$ systemctl --user list-timers
$ systemd-analyze calendar "Mon..Fri 07:30"      # check an expression and see the next trigger
$ journalctl --user -u backup.service

    Timers replace cron with logging, dependencies, Persistent= catch-up and RandomizedDelaySec=. OnCalendar accepts hourly, daily, weekly, Mon..Fri 07:30, *:0/15 (every 15 minutes); OnBootSec= and OnUnitActiveSec= give intervals. For a one-off: systemd-run --user --on-active=30m notify-send "tea".

    On the bench: a user unit is the clean way to keep a serial logger, MQTT bridge or OpenOCD server running: it restarts on failure, logs to the journal, and with a udev rule adding TAG+="systemd", ENV{SYSTEMD_USER_WANTS}="serial-log.service" it can start when the device is plugged in.

    Networking from the terminal

    Network debugging is walking up the stack with one tool per layer until something says no: link, address, route, name, port, protocol.

    You will be able to

    • Read interfaces, addresses, routes and neighbours with ip
    • See what is listening and who is connected with ss
    • Test names, ports and HTTP with dig, nc, curl, and capture packets with tcpdump

    The ladder

    1. Link: is the interface up with carrier? ip -br link
    2. Address: do I have an IP in the right subnet? ip -br addr
    3. Route: is there a path, and which interface does it use? ip route get 1.1.1.1
    4. Reachability: does the gateway answer? the target? ping -c 3
    5. Name: does the name resolve to what I think? dig +short name
    6. Port: is anything listening, and can I reach it? ss -tlnp, nc -zv host port
    7. Protocol: does it speak correctly? curl -v, tcpdump
    $ ip -br link
$ ip -br addr
$ ip addr show wlan0
$ ip route
$ ip route get 192.168.1.44
$ ip neigh  # the ARP table: IP to MAC on the local segment
$ ping -c 3 192.168.1.1
$ ping -c 2 192.168.1.99  # same subnet, no answer: "Host Unreachable" comes from ARP failing

    ip abbreviates everything (ip a, ip r, ip l), -br gives one line per interface, -4/-6 filter by family, -j emits JSON, and -c adds colour. In 192.168.1.57/24 the /24 says the first 24 bits are the network: anything in 192.168.1.0–255 is on-link, everything else goes via the default gateway. ifconfig, route, arp and netstat are the deprecated ancestors.

    On the bench: ip neigh after a ping sweep is the quickest way to find the IP a new board just got from DHCP, and the first three bytes of the MAC identify the vendor (24:6f:28 is Espressif).

    Packets

    $ tcpdump -ni wlan0  # needs root

    -n skips name lookups, -i picks the interface, -c N stops after N packets, -A prints payloads as text, and -w file.pcap saves a capture you can open in Wireshark. The filter language (BPF) reads naturally: host 192.168.1.44 and not port 22, tcp[tcpflags] & tcp-syn != 0.

    Security lens: put an IoT device on a network you control and run sudo tcpdump -ni wlan0 host DEVICE_IP -w dev.pcap while it boots. DNS queries reveal its cloud endpoints, plain HTTP reveals firmware update URLs, and an unexpected open port (like 2323 on the camera in this sandbox) is an invitation to look closer with nc.

    A service shows as listening on 127.0.0.1:5000. Another machine cannot connect. Why?

    ping host works but curl http://host says connection refused. What does that tell you?

    "Refused" is an active answer (a TCP RST). A firewall that drops silently would give a timeout instead.

    Why curl -f in scripts?

    HTTP errors are valid responses as far as the transfer is concerned. -f turns them into exit status 22.

    Check yourself

    Load average is 6.0 on a 2-core machine, yet CPU is 90% idle. What is going on?

    Linux counts tasks in state D in the load average. High load with idle CPU points at storage or a hung network filesystem.

    free shows 200 MiB free but 5 GiB available. Should you worry?

    Unused RAM is wasted RAM, so the kernel caches files in it. "available" is the number that matters.

    time make: real 2m10s, user 0m8s, sys 0m3s. Where did the time go?

    real minus (user + sys) is time off-CPU. strace -T would show the slow calls.

    udev rules

    udev is the daemon that creates /dev nodes when the kernel announces hardware. Rules in /etc/udev/rules.d/*.rules match device attributes with == and assign properties with = or +=. Ask udev what you can match on:

    $ udevadm info -a /dev/ttyUSB0  # walks up the device tree: attributes at each level
$ udevadm info /dev/ttyUSB0  # the properties udev already set
$ cat /etc/udev/rules.d/50-example.rules

    # /etc/udev/rules.d/99-bench.rules   (one rule per line, comma-separated)
# a stable name for the ESP32 dev board, usable by group uucp
SUBSYSTEM=="tty", ATTRS{idVendor}=="10c4", ATTRS{idProduct}=="ea60", SYMLINK+="esp32", MODE="0660", GROUP="uucp"
# two identical bridges? add the serial number
SUBSYSTEM=="tty", ATTRS{idVendor}=="0403", ATTRS{idProduct}=="6001", ATTRS{serial}=="A50285BI", SYMLINK+="target_uart"
# raw USB access for a debug probe without root (matches the usb device, not a tty)
SUBSYSTEM=="usb", ATTR{idVendor}=="0483", ATTR{idProduct}=="3748", MODE="0660", GROUP="uucp", TAG+="uaccess"

    $ echo 'SUBSYSTEM=="tty", ATTRS{idVendor}=="10c4", ATTRS{idProduct}=="ea60", SYMLINK+="esp32"' | sudo tee /etc/udev/rules.d/99-esp32.rules
$ sudo udevadm control --reload
$ sudo udevadm trigger
$ ls -l /dev/esp32

    Why bother: ttyUSB0 is assigned in plug order. With two adapters, the target console and the flasher swap names depending on which you plugged in first, and one day you flash the wrong board. A symlink keyed on vendor, product and serial number never moves. Debug rules with udevadm test $(udevadm info -q path /dev/ttyUSB0) and watch events with udevadm monitor.

    Talking over the line

    A tty device has line settings: speed, data bits, parity, stop bits, flow control, and a "cooked" mode that echoes and edits lines, which you do not want when talking to a microcontroller. stty reads and writes them.

    $ stty -F /dev/ttyUSB0  # current settings: 9600 baud
$ cat /dev/ttyUSB0  # garbage: the board talks at 115200
$ stty -F /dev/ttyUSB0 115200 raw -echo
$ cat /dev/ttyUSB0
$ picocom -b 115200 /dev/ttyUSB0

    Garbage characters almost always mean a baud mismatch; nothing at all means TX/RX swapped, no common ground, or the wrong port. With the line configured, plain shell tools work: cat /dev/ttyUSB0 | tee boot.log captures, echo -ne 'help\r' > /dev/ttyUSB0 sends, and ts (moreutils) timestamps each line.

    Capstone: six jobs, no hand-holding

    Each mission below is a small real task of the kind that lands on your desk: an incident to triage, a report to produce, files to reorganise. They combine everything from the earlier modules, and none of them needs more than a few lines.

    How to approach them

    • Look at the data first: head, wc -l, cut one line apart by hand
    • Build the pipeline one stage at a time, checking the output after each |
    • Preview anything destructive with echo in front before you run it for real

    The method

    1. State the question as a sentence. "For each hour, how many requests?" already names the key (hour) and the operation (count).
    2. Find the key in one line. Which separator isolates it? head -1 FILE | cut -d: -f2, or awk '{print $4}'.
    3. Filter early. Drop the lines you do not need with grep or an awk pattern before doing anything expensive.
    4. Normalise, then aggregate. sort | uniq -c, or an awk array when you need sums or more than one key.
    5. Rank and trim. sort -rn | head.
    6. Promote it. When you have run the same line three times, put it in a script with set -euo pipefail and arguments.
    $ head -2 logs/access.log
$ head -1 logs/access.log | cut -d: -f2  # the hour
$ head -3 logs/auth.log
$ grep -c . logs/access.log logs/auth.log logs/app.log
$ for f in photos/*.jpeg; do echo mv "$f" "${f%.jpeg}.jpg"; done  # dry run: echo first
