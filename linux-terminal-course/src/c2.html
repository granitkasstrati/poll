grep and regular expressions

Logs, configs, source code, serial captures: it is all text, and a regular expression is how you describe the lines you care about. Learn one dialect properly and the rest are footnotes.

You will be able to

  • Write extended regular expressions with anchors, classes, quantifiers, groups and back-references
  • Drive grep's options: count, invert, only-matching, context, recursive, fixed strings
  • Know the differences between BRE, ERE and PCRE, and between a regex and a glob

The building blocks

PieceMatchesPieceMatches
.Any one character^ / $Start / end of line (zero width)
[abc] [a-f0-9]One character from the set[^abc]One character NOT in the set
*Previous item, 0 or more times+ / ?1 or more / 0 or 1
{n} {n,m} {n,}Exactly n / n to m / at least na|bEither alternative
( )Group, and capture for \1\b or \< \>Word boundary
[[:digit:]] [[:space:]]POSIX classes, used inside brackets\. \[ \$The literal character

Quantifiers are greedy: ".*" on a "b" c "d" matches from the first quote to the last. The portable fix is a negated class, "[^"]*", which cannot run past the closing quote. A regex * is not a glob *: in a regex, "anything" is .*.

Experiments for the lab: ^[A-Z][a-z]{2} +[0-9]+, ([0-9a-f]{2}:){5}[0-9a-f]{2}, [0-9]+\.[0-9]+V, \b[0-9]{4,}\b, (Failed|Accepted) [a-z]+.

Three dialects

DialectUsed byNotes
BRE (basic)grep, sed by default+ ? | ( ) { } are literal unless backslashed: \(ab\)\+
ERE (extended)grep -E, sed -E, awk, bash =~The sane default. Use it always
PCRE (Perl)grep -P, ripgrep, Python, most languagesAdds \d \w \s, lazy *?, lookaround (?=...) (?<!...)

Always single-quote the pattern so the shell passes it through untouched.

grep in practice

$ grep ERROR logs/app.log
$ grep -c ERROR logs/app.log  # count matching lines
$ grep -n 'crc' logs/app.log  # with line numbers
$ grep -i 'warn' logs/app.log | head -3
$ grep -v INFO logs/app.log | grep -vc DEBUG  # invert
$ grep -E 'ERROR|WARN' logs/app.log | grep -c mqtt
$ grep -oE 'rssi -[0-9]+' logs/app.log | sort -u  # only the matching part
$ grep -w 'ok' logs/app.log  # whole word: skips "broker"
$ grep -rn 'baud' src conf  # recursive
$ grep -rl 'TODO' src  # just the file names
$ grep -A2 'bad sha256' logs/app.log | head -6  # 2 lines of context after
$ grep -F '[ERROR]' logs/app.log | wc -l  # fixed string: no regex at all
$ grep -q 'node-d' data/sensors.csv && echo present  # quiet: just the exit status

Patterns you will actually reuse

$ grep -oE '([0-9]{1,3}\.){3}[0-9]{1,3}' logs/access.log | sort -u  # IPv4-shaped
$ grep -Ev '^\s*(#|$)' conf/sshd_config  # strip comments and blanks
$ grep -E '" (4|5)[0-9]{2} ' logs/access.log | wc -l  # HTTP 4xx and 5xx
$ grep -E '^[^,]*,node-[bd],' data/sensors.csv | head -3  # anchored to a CSV column
$ grep -E '(.)\1' /usr/share/dict/words | head -5  # back-reference: doubled letter
$ grep -cE '^(.).*\1$' /usr/share/dict/words  # starts and ends with the same letter
ripgrep (rg) is grep with recursion, .gitignore awareness and Rust-regex syntax by default. rg -n TODO equals grep -rn TODO . minus build junk. Use it locally; keep grep fluent for every other machine.

Check yourself

Which pattern matches a line that consists only of digits?

Without anchors a pattern matches anywhere in the line, and [0-9]* even matches the empty string, so it matches every line.

grep 'a+b' file (no -E) looks for…

In basic regex + is an ordinary character. Use -E, or a\+b in GNU grep.

You want only the MAC addresses from a log, one per line. Which flag is essential?

-o prints each match instead of the whole line. Pair it with -E and sort -u.

In a script: if grep -q "$user" /etc/passwd; then. What is wrong?

Anchor to the field: grep -q "^$user:" /etc/passwd, or use getent passwd "$user" or id "$user".

sed: edit text without opening it

sed applies a small program to each line of its input. Ninety percent of real use is substitution and line selection, and those two cover config edits, log slicing and bulk refactors.

You will be able to

  • Substitute with capture groups, alternative delimiters and flags
  • Select lines by number, pattern and range, and print, delete or change them
  • Edit files in place safely

The model

For each input line: read it into the pattern space, run every command whose address matches, then print the pattern space (unless -n). A command looks like [address]command.

AddressSelectsCommandDoes
5Line 5s/re/rep/flagsSubstitute
$The last linepPrint (use with -n)
/re/Lines matching redDelete the line
3,7   /a/,/b/Inclusive rangesqQuit (after printing)
addr!Everything excepta text / i text / c textAppend / insert / replace line
0~3 (GNU)Every 3rd liney/abc/xyz/Translate characters

Substitution

$ echo 'baud=9600 baud=9600' | sed 's/9600/115200/'  # first match per line
$ echo 'baud=9600 baud=9600' | sed 's/9600/115200/g'  # every match
$ echo 'baud=9600 baud=9600' | sed 's/9600/115200/2'  # only the second
$ echo '/usr/local/bin' | sed 's|/usr/local|/opt|'  # any delimiter: no leaning toothpicks
$ echo 'Error error ERROR' | sed 's/error/E/gI'  # case-insensitive
$ echo 'port 8080' | sed -E 's/[0-9]+/[&]/'  # & is the whole match
$ echo '2026-11-10' | sed -E 's/([0-9]+)-([0-9]+)-([0-9]+)/\3.\2.\1/'  # reorder with groups
$ sed -E 's/^([^,]*),([^,]*),.*/\2 -> \1/' data/parts.csv | head -4

Use -E so groups are plain ( ). In the replacement, & is the entire match and \1…\9 are the groups. The p flag prints lines where a substitution happened, which with -n gives you "grep and transform" in one step:

$ sed -nE 's/.*rssi (-[0-9]+).*/\1/p' logs/app.log | sort -n | head -3
$ sed -nE 's/^interval=(.*)/\1/p' /etc/sensor-logger.conf  # read one config value

Selecting lines

$ sed -n '3p' data/parts.csv  # just line 3
$ sed -n '2,4p' data/parts.csv
$ sed -n '$p' data/parts.csv  # last line
$ sed '1d' data/parts.csv | head -3  # drop the header
$ sed -n '/BEGIN/,/END/p' conf/device.pem  # between two markers
$ sed '/^#/d; /^$/d' conf/serial.conf  # two commands, separated by ;
$ sed -n '/ERROR/{s/^[^ ]* //;p}' logs/app.log | head -3  # a block on matching lines
$ sed '3q' logs/access.log | cut -c1-50  # like head -3, and stops reading
$ sed -n '/node-d/=' data/sensors.csv | head -3  # print line numbers of matches

Editing files in place

-i rewrites the file. Always look at the result without -i first, and keep a backup with a suffix until you trust the expression: sed -i.bak '...' file.

$ cat conf/serial.conf
$ sed 's/^parity=none/parity=even/' conf/serial.conf  # preview on stdout
$ sed -i.bak 's/^parity=none/parity=even/' conf/serial.conf
$ diff conf/serial.conf.bak conf/serial.conf
$ sed -i '/^stopbits/a flow=none' conf/serial.conf; tail -3 conf/serial.conf  # append after a match
$ sed -i -E 's/^#?(PermitRootLogin).*/\1 no/' conf/sshd_config; grep PermitRoot conf/sshd_config

That last form is the standard way to set a config key whether or not it is currently commented out: optional #, capture the key, replace the whole line.

Anchor your patterns. s/9600/115200/ will also rewrite a comment, a port number or a timestamp that happens to contain 9600. s/^baud=9600$/baud=115200/ changes exactly one thing. macOS/BSD sed differs: -i '' needs an explicit empty suffix and several GNU extensions are missing.

When to stop using sed

sed works line by line and has no notion of fields or numbers. If you find yourself reaching for the hold space (h, G, x) or counting columns, switch to awk. If the data is JSON or YAML, use jq or yq: regexes cannot parse nested structures.

Check yourself

What does sed -n '/start/,/stop/p' f print?

A two-address range. If "stop" never appears, it runs to the end of the file. It can match several blocks.

Why write s|/var/www|/srv/http| instead of using slashes?

The character after s becomes the delimiter. s#a#b# and s,a,b, work too.

sed 's/a/b/' file > file leaves the file…

The shell truncates the output file before sed reads it. Use -i, which writes a temp file and renames it.

awk: a programming language for columns

awk reads records, splits them into fields, and runs your pattern-action rules. It has variables, arithmetic, associative arrays and printf. For tabular text it replaces most small Python scripts.

You will be able to

  • Select and reformat fields with any separator
  • Filter rows with numeric and regex conditions
  • Aggregate with associative arrays: counts, sums, averages, min and max per key

The program shape

awk 'BEGIN { setup }  pattern { action }  pattern { action }  END { summary }' file

For every input line awk sets $0 (the line), $1…$NF (the fields), NF (field count) and NR (line number), then runs each rule whose pattern is true. A rule with no action prints the line; a rule with no pattern runs on every line.

$ awk '{print $1}' logs/access.log | head -3  # first whitespace-separated field
$ awk '{print $1, $9, $NF}' logs/access.log | head -3  # comma = output separator (space)
$ awk -F, '{print $2}' data/parts.csv | head -4  # -F sets the input separator
$ awk -F: '$3 >= 1000 {print $1, $7}' /etc/passwd  # numeric condition
$ awk -F, 'NR > 1 && $4 >= 4' data/parts.csv  # pattern only: print the line
$ awk '/ERROR/ {n++} END {print n, "errors"}' logs/app.log
$ awk 'NR == 5, NR == 7' logs/app.log  # a range of records
$ awk 'END {print NR}' logs/access.log  # wc -l
$ awk '{print NF}' logs/app.log | sort -n | uniq -c  # how many fields per line?

Always wrap the program in single quotes: awk's $1 must reach awk, not be expanded by the shell. To pass a shell value in, use -v name="$value".

Conditions and regexes

$ awk '$9 == 404' logs/access.log | wc -l
$ awk '$9 >= 400 {print $9, $7}' logs/access.log | sort | uniq -c | sort -rn | head -4
$ awk '$7 ~ /^\/api\//' logs/access.log | wc -l  # field matches regex
$ awk '$1 !~ /^192\.168\./ {print $1}' logs/access.log | sort -u  # does not match
$ awk -F, -v limit=3.3 'NR > 1 && $5 < limit {print $2, $5}' data/sensors.csv | head -4
$ awk -F'[][]' '{print $2}' logs/access.log | head -2  # a regex as separator: text inside [ ]

printf and built-in functions

$ awk -F, 'NR > 1 {printf "%-4s %-18s %3d x %6.3f = %7.2f\n", $1, $2, $4, $5, $4*$5}' data/parts.csv
$ awk -F, 'NR > 1 {print toupper($2), length($2)}' data/parts.csv | head -3
$ awk '{print substr($4, 2, 11), substr($4, 14, 5)}' logs/access.log | head -2  # date and time
$ awk '{split($4, t, ":"); print t[2]}' logs/access.log | sort | uniq -c  # requests per hour
$ awk '{gsub(/[0-9]+/, "N"); print}' logs/app.log | cut -c1-60 | head -3
$ awk 'BEGIN {printf "%.4f V per LSB\n", 3.3 / 4096; print 2^10, 17 % 5, int(7/2)}'
On the bench: a BEGIN-only program is a floating-point calculator that reads no input: ADC scaling, RC time constants (awk 'BEGIN{print 10e3*100e-9}'), baud-rate divisor error. printf "%x" and strtonum("0x1F") (gawk) cover hex.

Associative arrays: the reason to learn awk

An array indexed by strings turns "group by" into one line. Accumulate while reading, report in END.

$ awk '{c[$1]++} END {for (ip in c) print c[ip], ip}' logs/access.log | sort -rn | head -4
$ awk '{b[$9] += $10} END {for (s in b) print s, b[s]}' logs/access.log | sort
$ awk -F, 'NR > 1 {s[$2] += $3; n[$2]++} END {for (k in s) printf "%s %.2f\n", k, s[k]/n[k]}' data/sensors.csv | sort
$ awk -F, 'NR > 1 && (!($2 in lo) || $5 < lo[$2]) {lo[$2] = $5} END {for (k in lo) print k, lo[k]}' data/sensors.csv | sort
$ awk '!seen[$1]++ {print $1}' logs/access.log | head -5  # unique, keeping first-seen order
$ awk -F'[][ ]+' '{c[$3]++} END {for (l in c) print l, c[l]}' logs/app.log | sort  # lines per log level

!seen[$1]++ deserves a second look: the first time a key appears its count is 0 (false), ! makes it true so the line prints, and ++ ensures every later occurrence is false. It is sort -u without sorting. The iteration order of for (k in arr) is unspecified, so pipe to sort when order matters.

Useful variables

VariableMeaningVariableMeaning
NR / FNRRecord number overall / in the current fileNFNumber of fields; $NF is the last one

$ awk 'BEGIN {FS = ","; OFS = "\t"} NR > 1 {print $1, $4, $5}' data/parts.csv | head -3  # CSV to TSV
$ awk 'NR == FNR {ok[$1]; next} FNR > 1 && !($2 in ok)' data/calibrated.txt FS=, data/sensors.csv | cut -d, -f2 | sort -u

The second line is the classic two-file idiom: while NR == FNR awk is still in the first file, so it loads a lookup table and skips to the next record; afterwards it filters the second file against that table. It is a join without sorting.

Real CSV has quoted fields with embedded commas. -F, is fine for data you control; for anything else use gawk --csv (5.3+), mlr (Miller) or xsv.

Check yourself

What does awk '$3 > 100' file do?

A pattern without an action defaults to {print $0}.

Why does awk "{print $1}" file print whole lines?

In double quotes the shell substitutes its own $1. Single-quote awk programs.

Which prints the sum of column 2?

Accumulate per line; report once in END. Uninitialised variables start as 0 or the empty string.

In awk 'NR==FNR {a[$1]; next} $1 in a' A B, which lines are printed?

The first rule only runs for A (where NR equals FNR), stores the keys, and skips the second rule. The second rule then filters B.

The pipeline toolkit: sort, uniq, cut, tr, find, xargs, jq

A dozen small filters, each trivial alone. The skill is composition: seeing a question as a sequence of extract, normalise, sort, count, rank.

You will be able to

  • Build frequency tables and top-N reports from any log
  • Compare and join sorted lists with comm and join
  • Find files by any property and act on them safely with -exec and xargs

The frequency-table idiom

$ cut -d' ' -f1 logs/access.log | sort | uniq -c | sort -rn | head -5
$ awk '{print $9}' logs/access.log | sort | uniq -c | sort -rn
$ grep -oE '\[(ERROR|WARN)\] [a-z]+' logs/app.log | sort | uniq -c | sort -rn

Extract the key, sort so equal keys are adjacent, uniq -c to count runs, sort -rn to rank. uniq only collapses adjacent duplicates, which is why the first sort is not optional.

sort

$ sort -t, -k4,4nr data/parts.csv | head -4  # by column 4, numeric, descending
$ sort -t, -k3,3 -k5,5n data/parts.csv | head -5  # by package, then price
$ du -sh ~/work/* | sort -h  # human sizes: 4.0K < 1.2M < 3G
$ sort -u data/calibrated.txt  # sorted and de-duplicated
$ sort -t: -k3,3n /etc/passwd | cut -d: -f1,3 | tail -4
$ printf 'v1.10\nv1.9\nv1.2\n' | sort -V  # version order

-k4,4 means "from field 4 to field 4". A bare -k4 means "from field 4 to the end of the line", which is rarely what you want. Suffix letters (n, r, h, V) apply to that key only.

cut, paste, tr, column

$ cut -d: -f1,7 /etc/passwd | head -3  # fields
$ cut -c1-19 logs/app.log | head -2  # character columns
$ cut -d, -f2- data/parts.csv | head -2  # field 2 to the end
$ head -1 data/sensors.csv | tr ',' '\n'  # one header per line
$ tr -d '\r' < fw/boot-capture.log 2>/dev/null | head -1  # strip CRs from a serial capture
$ echo 'a    b   c' | tr -s ' '  # squeeze repeats
$ echo 'Hello World' | tr 'A-Za-z' 'N-ZA-Mn-za-m'  # rot13
$ cut -d, -f2 data/sensors.csv | sort -u | paste -sd,  # join lines with commas
$ column -t -s, data/parts.csv | head -5  # align as a table

cut splits on exactly one delimiter character and cannot handle runs of spaces; for whitespace-aligned output (ps, ls -l, df) use awk '{print $N}' or squeeze first with tr -s ' '.

On the bench: Windows tools and most UART firmware emit \r\n. A stray \r makes grep 'ok$' miss, makes values compare unequal, and makes the terminal print over itself. Diagnose with cat -A (shows ^M$) or file ("with CRLF line terminators"); fix with tr -d '\r' or dos2unix.

Comparing lists: comm and join

$ cut -d, -f2 data/sensors.csv | sed 1d | sort -u > /tmp/seen.txt
$ comm /tmp/seen.txt data/calibrated.txt  # 3 columns: only-left, only-right, both
$ comm -23 /tmp/seen.txt data/calibrated.txt  # only in the first
$ comm -12 /tmp/seen.txt data/calibrated.txt  # in both
$ join -t, -1 1 -2 1 <(sort data/parts.csv) <(printf 'C1,in stock\nU1,ordered\n')

Both need sorted input. comm -23 A B is set difference, comm -12 is intersection, and sort -u A B is union.

find

find START tests... action walks a tree and evaluates the expression for every entry. Tests are ANDed; -o is OR, ! negates, and escaped parentheses group.

$ find src -name '*.c'  # quote the pattern or the shell expands it first
$ find src -type f -name '*.[ch]' | wc -l
$ find ~/work -type d -maxdepth 1
$ find ~/work -type f -size +2k
$ find ~/work -type f -newer conf/device.pem | head -5
$ find /usr/bin -perm -4000  # setuid programs
$ find ~/work -type f ! -name '*.c' ! -name '*.h' -path '*src*'
$ find ~/work \( -name '*.tmp' -o -name '*.bak' \)
$ find ~/work -type f -empty
$ find ~/work -name '*.log' -exec wc -l {} +  # one wc for all files
$ find src -name '*.c' -exec grep -l TODO {} \;  # one grep per file

xargs

xargs turns lines of input into arguments for a command. By default it splits on any whitespace, so it breaks on file names with spaces unless you use the NUL-separated pair find -print0 | xargs -0.

$ find src -name '*.c' | xargs wc -l | tail -1
$ find ~/work -name '*.jpeg' | xargs ls -l  # breaks on "board top.jpeg"
$ find ~/work -name '*.jpeg' -print0 | xargs -0 ls -l  # correct
$ cut -d, -f2 data/sensors.csv | sed 1d | sort -u | xargs -I{} echo "calibrating {}..."
$ seq 1 6 | xargs -n 2 echo pair:
$ printf 'node-a\nnode-b\n' | xargs -I% grep -c % data/sensors.csv

-I{} runs the command once per input line with the placeholder substituted; -n N caps the arguments per invocation; -P 4 runs four in parallel; -r skips the run when there is no input.

jq for JSON

Do not grep JSON. jq is to JSON what awk is to columns.

$ curl -s localhost:8080/api/nodes | jq .
$ curl -s localhost:8080/api/nodes | jq '.[0].id'
$ curl -s localhost:8080/api/nodes | jq -r '.[].id'  # -r: raw strings, no quotes
$ curl -s localhost:8080/api/nodes | jq -r '.[] | select(.vbat < 3.3) | .id'
$ curl -s localhost:8080/api/nodes | jq 'length'
$ curl -s localhost:8080/health | jq -r .version
$ ip -j addr | jq -r '.[] | select(.operstate == "UP") | .ifname'

Many modern tools emit JSON on request (ip -j, lsblk -J, journalctl -o json, systemctl --output=json), which is far more robust to parse than their human-readable tables.

Check yourself

uniq -c on unsorted input gives…

uniq compares each line only with the previous one. Sort first.

Why find . -name '*.c' with quotes?

If the current directory contains a.c and b.c, find would receive -name a.c b.c and fail or search for the wrong thing.

Difference between -exec cmd {} \; and -exec cmd {} +?

+ behaves like xargs and is much faster when the command accepts multiple files.

Which sorts du -sh output correctly?

-n would rank 900K above 2G. -h understands the unit suffixes.
